# 공개 배포 경계와 점검

이 문서는 공개 배포 시 지켜야 할 범위와 재검증 항목을 설명합니다. 개인 운영 감사 원본, 실제 식별자, 운영 기록과 정리 전 커밋 주소는 공개 문서에 포함하지 않습니다.

## 공개 코드와 비공개 운영 설정

- 공개 배터리 예제는 차량과 연결되지 않은 미설정 상태입니다. 개인 교정값은 저장소 밖에서 보관하며, 배포 시 `BATTERY_ANALYSIS_CONFIG_JSON` 또는 비공개 Compose override로 공급합니다. [설치와 운영](operations.md)을 참고하세요.
- `compose.yaml`도 공개 대상입니다. `x-source`는 경로가 저장소 내부인지 검사할 뿐 Git 추적 여부나 개인정보 포함 여부를 보장하지 않습니다. 비공개 파일을 inline 입력으로 넣지 마세요.
- 주소·호스트·사용량을 설명하는 문서와 테스트에는 일반 예제나 합성값을 사용합니다. 안정적인 차량 가명도 실제 활동과 연결될 수 있으므로 운영 가명은 공개하지 않습니다.
- `.gitignore`는 로컬 `.env`, 가상환경과 비공개 교정 파일의 실수로 인한 추가를 줄여 줍니다. Git 이력이나 이미 생성된 파일에서 정보를 삭제하는 기능은 아닙니다.

원래 운영 저장소와 새 공개 저장소는 분리합니다. 원본 이력·PR·운영 설정은 비공개 저장소에 보존하고, 공개 저장소에는 정리한 일반 branch 이력과 공개용 문서만 가져옵니다. 운영 GitOps는 비공개 저장소를 계속 사용하며 공개 저장소의 push를 운영 배포로 연결하지 않습니다.

## 공개 전 검사

1. 현재 공개 파일, 모든 공개 branch의 도달 가능한 blob, 커밋 작성자·committer·메시지를 검사합니다. 알려진 운영 식별자·주소·개인 경로의 검사와 비밀키 검사는 서로 대체할 수 없습니다.
2. [Gitleaks](https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1)를 사용해 현재 파일과 전체 공개 이력을 검사합니다. CI는 고정 버전·SHA256을 검증하고 결과를 가리며 `gitleaks:allow` 주석을 무시합니다. [개발과 검증](development.md)에 명령이 있습니다.
3. 원본 조각에서 생성한 `compose.yaml`의 byte 일치, 환경변수 계약, 모든 Compose 프로필과 오프라인 회귀 검사를 확인합니다. PR CI는 `pull_request`와 읽기 권한을 사용하며 운영 비밀을 공급하지 않습니다.
4. README 링크와 Mermaid 다이어그램을 렌더링합니다. 개인정보가 있는 실제 대시보드·차량 화면을 공개 예제로 사용하지 않습니다.
5. 새 GitHub 저장소의 branch, PR, 이슈, Actions 로그·artifact, release, wiki와 보안 설정을 확인합니다. 비공개 운영 자산은 새 공개 저장소로 복사하지 않습니다.
6. 비공개 운영 저장소의 이름이나 GitOps URL을 바꿀 때는 해당 자동 동기화를 잠시 중지합니다. 저장소 접근과 원래 설정의 동일성을 확인한 뒤 복구하고, 컨테이너 ID뿐 아니라 시작·종료 시각, 볼륨과 `.env`의 동일성도 확인합니다. 실행 중 프로젝트에서는 `redeployAfterSync=false`만으로 재배포를 막을 수 없습니다.

기존 저장소의 현재 파일만 바꾸거나 branch를 force-push해도 과거 PR ref와 GitHub cache가 사라지는 것은 아닙니다. 같은 저장소에서 민감 정보를 제거하려면 [GitHub의 민감 데이터 제거 절차](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)를 따르세요. 실제 자격 증명이 발견되면 파일 정리보다 폐기·교체가 먼저입니다.

## 라이선스와 기여

프로젝트의 자체 코드와 문서는 [MIT](../LICENSE)입니다. 외부 이미지·패키지·DBC·VSS 정의·단가표·NASA 데이터의 조건은 별개이며 [외부 출처 고지](../THIRD_PARTY_NOTICES.md)에 정리했습니다. 운영자가 제공하는 정의나 데이터의 공유 권리를 이 프로젝트가 부여하지 않습니다.

기여 범위와 생성물 규칙은 [CONTRIBUTING](../CONTRIBUTING.md), 비공개 취약점 신고는 [SECURITY](../SECURITY.md)를 참고하세요. 공개 이슈에는 토큰·VIN·좌표·원시 CAN·사용자 대화·개인 로그를 올리지 마세요.

## 확인 한계

- 자동 검사는 알려진 식별자와 규칙 기반 탐지를 확인하며 모든 개인정보·새 키 형식·인코딩된 값의 부재를 인증하지 않습니다.
- 오프라인 CI 성공은 실제 차량, SocketCAN, S3 사업자, 운영 데이터베이스나 모든 클라이언트 버전의 동작 증거가 아닙니다. 선택 의존성·외부 소스가 없어 건너뛴 검사는 결과에 명시합니다.
- 이미지 태그와 패키지 버전 고정은 불변 digest, 취약점 부재나 영구 지원을 뜻하지 않습니다. 의존성 갱신·실제 사용자용 합성 데모·다국어 문서는 필요가 확인될 때 추가합니다.
- 일반 공개 branch 이력만 이관합니다. 원본 PR 토론·리뷰·로그·wiki·비공개 운영 설정은 원래 저장소에 남으며 공개하지 않습니다.
